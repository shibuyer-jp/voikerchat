# T-34: プレミアム専門シーン5本の追加 + Kaigotalk 向けデータ設計

## 目的
「アニメシーンだけではプレミアムが弱い」という課題への対応。実用的・専門的なシーンをプレミアムの中核価値に据える。介護・医療系シーンの利用データは、次期プロダクト **Kaigotalk** の市場検証に活用する。

## 追加シーン(id 14〜18、isPremium: true)
既存の病院シーン(id 5)は「患者としての会話」なので、プレミアムは**「日本で働く外国人」視点**で差別化する。ターゲット(フィリピン人学習者)の実需=就労日本語に直結させる。

| id | シーン名 | キャラ | 内容 | 推奨レベル |
|----|---------|--------|------|-----------|
| 14 | 介護のしごと | Haruko(利用者の高齢女性) | 介護施設での声かけ・体調確認・食事介助の会話。**Kaigotalk 直結** | 中級 |
| 15 | 医療スタッフ | Dr. Mori(医師) | 看護助手・医療現場スタッフとしての申し送り・報告 | 上級 |

## 実装手順
1. `scene_service.dart` に5シーン追加。シーン名/説明は ARB のラベルヘルパー(`label_helpers.dart`)の既存パターンに従い3言語対応。
2. `api/chat.ts` のシステムプロンプトにシーン別ペルソナを追加(既存8+5シーンの実装パターンを踏襲)。各シーンの語彙レベル・敬語度・キャラ口調を明記。特に id 14/15 は介護・医療の頻出語彙(バイタル、食事介助、申し送り等)を自然に登場させる指示を入れる。
3. **重要**: `usage_logs.scene_id` は smallint。id 14〜18 をそのまま入れられるが、文字列シーンIDは従来通り `metadata.scene` に入れる(既存規約)。
4. シーン選択画面: プレミアムセクションを「実用シーン」「アニメシーン」の2グループに分け、実用シーンを上に配置。

## Kaigotalk 向けデータ設計(集計統計のみ、会話生文は保存しない)
既存 `usage_logs`(append-only、owner-scoped RLS)の範囲内で完結させ、**スキーマ変更・新規テーブルは作らない**:
- `session_start` / `message_sent` の `metadata` に `{ scene: "kaigo", turns, duration_sec, user_level }` を記録(既存イベントの範囲)
- 見たい指標: 介護/医療シーンの選択率・完走率・リピート率・平均ターン数(→ Kaigotalk の需要仮説検証)
- 集計は Supabase ダッシュボードの SQL で月次確認(クエリ例を `internal-docs/` にメモとして残す)
- **プライバシー**: 会話本文は保存しない現行方針を維持。集計目的の利用がプライバシーポリシーの記載範囲か Phase B で確認

## 受け入れ基準
- 5シーンが3言語で表示・会話でき、各キャラの口調・語彙レベルが仕様通り(手動で各シーン3往復以上の動作確認)
- ロック/解放が T-33 と正しく連動
- `flutter analyze` / `flutter test` 緑(scene 数のテストがあれば更新)
