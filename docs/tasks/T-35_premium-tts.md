# T-35: 高品質TTS導入(3段構成: 端末TTS / 広告日解放 / プレミアム常時)

## 方針(2026-07-16 ユーザー決定・確定版)
「音声品質は妥協しない」。プロバイダは **OpenAI TTS を第一候補**(ユーザーがサンプル品質を確認・承認済み)。
構成は3段のハイブリッド:

| 層 | 音声 | 条件 |
|---|---|---|
| 無料(基本) | 端末内蔵TTS(コスト0) | いつでも。お試しはこれで完結 |
| 無料(広告特典) | **クラウドTTS(その日いっぱい)** | リワード広告を1回視聴した日。既存の「+5往復」特典に相乗り |
| プレミアム | クラウドTTS常時 | 広告なし |

狙い: 広告視聴に「回数+5」と「今日は良い声」の2特典を同時に載せ、良い声の体験時間を最大化 → 「端末TTSに戻れない」感覚が課金の後押しになる。広告を見ない人には一切コストが発生しない。

## コスト試算(OpenAI TTS $15/100万文字、AI返答1回≈80字)
- 無料ヘビー(10往復/日×毎日): 約$0.36/人・月
- プレミアムヘビー(月4.8万字): 約$0.7/人・月
※フィリピンのリワード広告単価は低め(推定$0.002前後/視聴)でTTS費を完全相殺しない日もあるが、差額は月数十円/人で許容(実測はAdMob運用後に検証)。単価は実装時に最新価格を再確認すること。

## 必須のセキュリティ設計(穴対策)
1. **サーバー側検証**: `api/tts.ts` は「本日 `ad_reward` イベントあり(usage_logs)」または「Premium entitlement」をサーバー側で検証してから音声を返す。クライアントのフラグだけで解放しない(API直叩きによるタダ乗り防止。T-01 と同じ思想)。
2. **日次判定の共用**: 「その日」の判定は rate_limits の日次リセットと同一ロジック/タイムゾーン基準を共用する(回数と音質でリセットタイミングがズレるバグを防ぐ)。
3. **広告在庫切れフォールバック**: リワード広告の読み込み失敗時は、その日のクラウドTTSを無償解放して良い(ユーザーに理不尽を与えない。発生率・コストとも軽微)。

## UX規約(嫌みなく)
- ポップアップで広告を押し付けない。チャット画面の音声設定付近に常設の小さな導線: 「🎧 高品質ボイス — 広告を見て今日解放(プレミアムは毎日)」
- 広告視聴後トースト: 「+5回追加!今日は高品質ボイスでお楽しみください🎧」
- 広告ボタンは**常時表示**(1日1回)に変更する(従来の「枯渇後のみ表示」から変更。開幕視聴を可能にする)
- クラウドTTS失敗/オフライン時は端末TTSへ自動フォールバックし、会話を止めない

## 実装手順
1. `lib/services/voice/` に `TtsEngine` 抽象を定義。既存 `text_to_speech_service.dart` を `DeviceTtsEngine` として包み、`CloudTtsEngine` を追加。選択ロジック: Premium → cloud / 本日広告済み → cloud / それ以外 → device。
2. `api/tts.ts` を Vercel に新設(キーはサーバー側環境変数のみ)。入力=テキスト+キャラID、出力=mp3。上記サーバー側検証を実装。
3. クライアント再生: `just_audio`(または `audioplayers`)で mp3 再生。`tts_text_cleaner.dart` を共用。
4. キャラ音声マッピング: 18キャラ分のOpenAI音声ID割当表を `lib/constants/` に定数化。
5. 広告ボタン常時表示化: `rewarded_ad_service.dart` / 関連UIを変更(1日1回上限は維持)。視聴成功時に `ad_reward` を usage_logs へ記録(既存イベント)し、クラウドTTS解放フラグをローカルにも持つ(表示用)。
6. 監視: `usage_logs.metadata` に `{ feature: "cloud_tts", chars }` を記録し月次でコスト実測。

## 人間の作業

- 実機での聴感・レイテンシ確認(候補比較が不要になったため聴き比べスクリプトはスコープアウト。不満が出た場合のみ Google Chirp3 HD / ElevenLabs を再検討)

## 受け入れ基準
- 3段の切替が仕様通り動く(無料端末TTS→広告視聴→即日クラウドTTS→日付変更で端末TTSへ戻る)
- API直叩きで広告未視聴の無料ユーザーがクラウドTTSを取得**できない**こと(curl で確認)
- 機内モードで端末TTSへフォールバックし会話継続できる
- 応答受信→再生開始まで体感2秒以内(目安)
- `flutter analyze` / `flutter test` 緑、`api/tts.ts` 疎通確認
