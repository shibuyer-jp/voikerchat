# T-35: 高品質TTS導入(プレミアム限定・ハイブリッド構成)

## 方針(2026-07-16 ユーザー決定)
「音声品質は妥協しない。利益率が下がっても継続利用されるクオリティを優先する」。
ただしコスト分析(下記)より、**無料ユーザー=端末内蔵TTS維持 / プレミアム=クラウドTTS** のハイブリッドが最適(無料層のコスト0円を守りつつ、課金の目玉になる)。

## コスト試算(ヘビープレミアムユーザー: 月4.8万文字=20往復/日×80字想定)
| 候補 | 単価(100万文字) | 月コスト/人 | 特徴 |
|---|---|---|---|
| OpenAI TTS (gpt-4o-mini-tts) | ~$12〜15 | 約$0.7 | 安価・多言語自然、統合容易 |
| Google Chirp 3 HD | $30 | 約$1.4 | 日本語の自然さに定評、感情表現 |
| ElevenLabs (Flash/v3) | $50〜 | 約$2.5〜 | 品質最高評価(MOS首位)、最も高価 |

$12.99プランの1人あたり純利益は現状約$9.5 → 最悪ケースでも約$5〜7 に収まり事業として成立。
※単価は2026年前半時点の公開情報。実装時に最新価格を再確認すること。

## プロバイダ選定(人間の判断)
**同一5文(各キャラの代表セリフ)を3社で生成して聴き比べて決める。**
Claude Code は比較用スクリプト `tool/tts_compare.py`(3社APIで同一文を生成、mp3出力)を先に作成する。
評価軸: 日本語の自然さ > 学習者向けの聞き取りやすさ > レイテンシ > コスト。

## 実装手順
1. **抽象化**: `lib/services/voice/` に `TtsEngine` インターフェースを定義し、既存 `text_to_speech_service.dart` を `DeviceTtsEngine` として包む。新規 `CloudTtsEngine` を追加。プレミアム判定(`revenuecat_service.isPremium`)でエンジンを切替。設定画面に「高品質音声(プレミアム)」トグル。
2. **サーバー**: `api/tts.ts` を Vercel に新設。APIキーはサーバー側環境変数のみ(クライアント埋め込み禁止、CLAUDE.md 方針)。入力=テキスト+キャラID、出力=mp3。既存 `api/chat.ts` の認証・レート制限パターンを踏襲(プレミアム entitlement をサーバー側でも検証し、無料ユーザーの叩き逃げを防ぐ)。
3. **クライアント再生**: `just_audio`(または `audioplayers`)を追加し、mp3 ストリーミング再生。**失敗・オフライン・高レイテンシ時は端末TTSへ自動フォールバック**(会話が止まるのが最悪のUX)。
4. **キャラ音声マッピング**: シーンごとにプロバイダの音声ID(男女・年齢感)を割当てる定数表を `lib/constants/` に置く。18キャラ分。
5. **キャッシュ**: 定型文(挨拶・システム文言)は Supabase Storage にキャッシュしてコスト削減(動的な会話文はキャッシュ不可なので対象外)。効果が薄ければスコープアウト可。
6. **TTSテキスト前処理**: 既存 `tts_text_cleaner.dart` をクラウド側でも共用。
7. **監視**: `usage_logs.metadata` に `{ feature: "cloud_tts", chars }` を記録し、月次で実コストを検証。想定超過時はアラート(まず手動確認で可)。

## 人間の作業

- 聴き比べと最終決定

## 受け入れ基準
- プレミアムで自然な音声、無料で従来通り端末TTS
- 機内モードでクラウドTTSが端末TTSへフォールバックし会話が継続できる
- 応答テキスト受信→再生開始まで体感2秒以内(目安)
- `flutter analyze` / `flutter test` 緑、`api/tts.ts` の疎通確認
