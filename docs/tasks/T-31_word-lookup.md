# T-31: 単語タップ辞書機能(AIメッセージ内の語句の意味を調べる)

## 背景(事実)
2026-07-16 時点で、この機能は**コード・設計書・タスク台帳のいずれにも存在しない**(未実装・未仕様化)。本書が初の正式仕様。

## 目的
AIの返答内の分からない語句をユーザーが選択 →「意味を調べる」で、読み方+意味(英語/タガログ語)+例文をその場で表示する。学習アプリとしての中核価値。

## 設計方針
日本語は分かち書きがなく単語境界のクライアント判定が難しいため、**「タップで単語分割」ではなく「範囲選択+コンテキストメニュー」方式**を採用する(実装コスト最小・誤分割ゼロ)。

1. **UI**: チャットのAIメッセージバブルを `SelectionArea` / `SelectableText.rich` 化し、`contextMenuBuilder` に「意味を調べる」アクションを追加(コピー等の標準項目は維持)。
2. **API**: 既存 `api/chat.ts` に `mode: "define"` を追加(または `api/define.ts` 新設)。入力=選択語句+前後文脈(その1メッセージ全文)、出力=JSON `{ reading, meaning_en, meaning_fil, example_ja, example_en }`。モデルは会話と同じ Claude Haiku(`claude-haiku-4-5-20251001`)、max_tokens 小さめ。
3. **表示**: ボトムシートで表示。読み仮名 / 英語 / タガログ語 / 例文。ローディング中インジケータ、失敗時 SnackBar(CLAUDE.md 方針)。
4. **クォータ**: 会話回数(rate_limits)は消費しない。ただし乱用防止に辞書専用の軽い日次上限(例: 無料30回/日、プレミアム無制限)をサーバー側で設ける。定数は `lib/constants/` へ。
5. **ログ**: `usage_logs` に `metadata: { feature: "define", scene: ... }` で記録(頻出語の分析は将来のコンテンツ改善に使う)。event type は既存の汎用のものを使い、スキーマ変更はしない。

## 受け入れ基準
- AIメッセージの任意の語句を選択 → 意味がボトムシートで2秒以内(目安)に表示される
- 選択→調べる→会話継続の間、チャット状態(入力欄・TTS再生)が壊れない
- オフライン/失敗時に分かりやすいエラー文言(ARB 3言語)
- `flutter analyze` / `flutter test` 緑、API側は Vercel デプロイ後に curl で疎通確認

## プライバシー注記
選択テキストが Anthropic API へ送信される。既存の会話送信と同一の扱いだが、Phase B のプライバシーポリシー確認項目に含めること。
